# شیوا گالری — تصمیم‌ها و نیازمندی‌ها

فروشگاه اینترنتی لباس زنانه. ریپوی قبلی (github.com/alirezaalamshah/Shiva-Gallery) فقط برای برداشتن مفاهیم خوانده شد؛ کد جدید از صفر نوشته می‌شود.

## تصمیم‌های قطعی

| موضوع | تصمیم |
|---|---|
| قابلیت توسعه | سایت قابل رشد و قابل واگذاری به فروشگاه‌های دیگر باشد، نه مخصوص شیوا گالری. اسم، لوگو، رنگ‌ها، دسته‌ها، سایزبندی، روش‌های ارسال و متن‌ها از پنل/تنظیمات بیایند، نه داخل کد. از تعداد کم تا زیاد محصول جواب بدهد (فیلتر، جستجو، زیردسته) |
| مدل چندفروشگاهی | فعلاً هر فروشگاه نصب جدا (سرور، دامنه و دیتابیس خودش). کد از ابتدا آماده‌ی تبدیل به پلتفرم چندفروشگاهی: تنظیمات فروشگاه در یک مدل مرکزی، بدون مقدار ثابت در کد، تا بعداً بدون بازنویسی کامل چندفروشگاهی شود |
| ساختار فنی | بک‌اند Django + DRF، فرانت Next.js (رندر سمت سرور برای سئو) |
| زیرساخت | بدون Docker. Celery و Redis هم فعلاً نه (پیشنهادی) |
| استایل | حرفه‌ای، جذاب، به‌یادماندنی، با انیمیشن‌های قوی. رنگ برند مشکی و طلایی (`#C9A24C`) از روی لوگو |
| دستگاه | ۹۹٪ مشتری‌ها با موبایل می‌آیند ← طراحی اول برای موبایل، دسکتاپ هم کامل |
| دسته‌های اصلی | از پیج اینستاگرام (instagram.com/shivagallery1335): مانتو مجلسی، مانتو اداری، عبا، شومیز و شلوار. دسته‌ها از پنل قابل تغییرند |
| فروشگاه حضوری | دزفول، خیابان شریعتی، بین پاساژ ولیعصر و بانک صادرات. تلفن: ۰۹۱۶۶۴۴۶۲۰۰. سفارش فعلاً از دایرکت اینستاگرام گرفته می‌شود. مغازه و پیج اینستاگرام موجودی و همه‌چیز جدا از سایت دارند ← نیازی به هماهنگی موجودی نیست |
| موجودی مشترک (۱۴۰۵/۰۸/۰۸) | تصمیم بالا عوض شد: از هر مدل فقط ۴ تا ۵ عدد هست و مغازه و سایت از یک موجودی می‌فروشند. پنل تعداد واقعی هر رنگ × سایز را می‌گیرد؛ سفارش اینترنتی خودکار کم می‌کند و فروش حضوری در صفحه‌ی «موجودی و فروش حضوری» با یک ضربه ثبت می‌شود. ذخیره‌ی جدول موجودی محصول فقط خانه‌های تغییرکرده را می‌فرستد و اگر در همین فاصله فروشی شده باشد، رد می‌شود تا فروش پاک نشود. به مشتری وقتی ۲ عدد یا کمتر مانده «فقط N عدد» نشان داده می‌شود و بیشتر از موجودی در سبد نمی‌رود |
| صندوق و نقش فروشنده (۱۴۰۵/۰۸/۰۹) | فروش مغازه در صفحه‌ی «صندوق فروش حضوری» (`/panel/pos`) ثبت می‌شود: جستجو یا اسکن کد کالا، فاکتور با چند قلم، تخفیف روی کل فاکتور، پرداخت نقد / کارت‌خوان / کارت به کارت یا ترکیبی، چاپ فاکتور ۸۰ میلی‌متری، و فهرست فروش روز با جمع هر روش پرداخت برای بستن صندوق. هر فروش با شماره‌ی فاکتور از همان موجودی سایت کم می‌شود. نقش سوم «فروشنده» اضافه شد: با نام کاربری و رمز وارد می‌شود، فقط صندوق و فروش‌های خودش را می‌بیند، تا سقف تخفیف تنظیم‌شده تخفیف می‌دهد و نمی‌تواند فروشی را باطل کند. ابطال فقط با مدیر است و کالا را به موجودی برمی‌گرداند. مدیر فروشنده‌ها را در «کاربران و دسترسی» می‌سازد و غیرفعال می‌کند. دکمه‌ی یک‌ضربه‌ای «فروش حضوری» صفحه‌ی موجودی حذف شد تا هر فروش مغازه فاکتور داشته باشد |
| سبد خرید (۱۴۰۵/۰۸/۰۹) | سبد در مرورگر می‌ماند، ولی جدا برای هر مشتری واردشده و یکی برای مهمان. با ورود، سبد مهمان به سبد مشتری اضافه می‌شود؛ با خروج، سبد مشتری برای خودش می‌ماند و از صفحه پاک می‌شود. سبد روی سرور نیست، پس بین گوشی و کامپیوتر یکی نمی‌شود |
| مرجوعی (۱۴۰۵/۰۸/۰۹) | مشتری بعد از ارسال یا تحویل و تا پایان مهلت مرجوعی، از صفحه‌ی سفارش درخواست مرجوعی یا تعویض می‌دهد (کدام کالا، چند عدد، دلیل). مدیر در «مرجوعی‌ها» تأیید یا رد می‌کند و پیام می‌گذارد؛ با «کالا رسید، انجام شد» کالا به موجودی برمی‌گردد. بازگشت پول یا تعویض بیرون از سایت انجام می‌شود |
| پنل مدیریت | پنل راحت و کاربردی برای افزودن لباس، دسته‌بندی، قیمت و هر چیز لازم. دو نقش در پنل: مدیر با دسترسی کامل و فروشنده فقط برای صندوق. داخل خود سایت در `/panel`، **طراحی اول برای کامپیوتر** (مدیر با کامپیوتر کار می‌کند؛ مشتری با موبایل). ورود مدیر با نام کاربری و رمز. پنل جنگو فقط ابزار پشتیبان است |
| ورود مشتری | فقط موقع پرداخت، با شماره موبایل و کد پیامکی. بدون رمز عبور |
| تسویه‌حساب | یک صفحه: موبایل و کد پیامکی، آدرس، روش ارسال، کد تخفیف، پرداخت؛ خلاصه‌ی سفارش ثابت پایین صفحه |
| سایز و مرجوعی | همه از پنل قابل تنظیم: جدول سایز هر دسته (کنار انتخاب سایز)، روشن/خاموش بودن مرجوعی، نوع آن (بازگشت پول یا فقط تعویض سایز)، مدت آن، و متن قوانین مرجوعی |
| ارسال | پیک داخل شهر (دزفول)، پست پیشتاز، تیپاکس. (تحویل حضوری از مغازه انتخاب نشد) |
| هزینه‌ی ارسال | فقط مبلغ ثابت برای هر روش (قابل تنظیم در پنل). ارسال رایگان نداریم |
| تم | روشن ولی گرم و بدون سفیدی خیره‌کننده: زمینه‌ی شنی/کتانی (`#EEE5D6`)، سطح‌های کرم (`#F7F1E7`) به‌جای سفید، مشکی و طلایی برای برند، و یک نوار قهوه‌ای تیره (`#2A211B`) برای محصول ویژه. خاص و جذاب، نه سفید و ساده |
| عکس محصولات | ترکیبی (هم تن مدل، هم زمینه‌ی ساده). سایت باید با هر دو خوب کار کند: قاب و نسبت یکسان، برش خودکار |
| عکس‌ها | هنگام آپلود در پنل، هر عکس در یک پنجره‌ی برش با قاب ۳:۴ سایت تنظیم می‌شود (کشیدن و بزرگ‌نمایی، یا برش خودکار همه). در مرورگر فشرده و بعد در سرور همیشه به WebP با اندازه‌ی ثابت ۱۲۰۰×۱۶۰۰ ذخیره می‌شود (لوگو ۶۰۰×۶۰۰). |
| قیمت تنوع‌ها | هر رنگ × سایز می‌تواند قیمت خودش را داشته باشد (جدول قیمت کنار جدول موجودی در پنل). قیمت حراج هم صریح برای هر رنگ × سایز در جدول جداگانه وارد می‌شود (حراج کلی محصول نداریم). در هر دو جدول یک قیمت را می‌شود یک‌جا روی همه، یا روی یک رنگ یا یک سایز اعمال کرد. خانه‌ی خالی در جدول قیمت یعنی قیمت خود محصول و در جدول حراج یعنی حراج نیست. کارت محصول ارزان‌ترین تنوع را نشان می‌دهد |
| آدرس | انتخاب استان و سپس شهرهای همان استان؛ «شهر دیگر» برای شهرهای خارج از فهرست |
| متن‌ها | متن‌های توضیحی اضافه که مشتری را سردرگم می‌کند حذف شد؛ «ورود با کد پیامکی» به جای «ورود با موبایل» |
| کپی‌رایت | تمامی حقوق وب‌سایت متعلق به شیوا گالری (نام فروشگاه از تنظیمات)؛ «طراحی و توسعه: هوشیوا» با لینک houshiva.ir در فوتر |
| پرداخت | درگاه پشت یک رابط قابل تعویض (`PAYMENT_GATEWAY`): `none` تا وقتی درگاه نیست (فروشگاه تلفنی هماهنگ می‌کند)، `zarinpal` (API نسخه‌ی ۴ با `auto_verify=false`)، و `fake` برای آزمایش روی سیستم. سفارش پرداخت‌نشده کالا را تا یک مهلت نگه می‌دارد (با درگاه ۲۰ دقیقه، بدون درگاه از پنل، پیش‌فرض ۲۴ ساعت) و بعد خودکار لغو می‌شود. پیامک ثبت سفارش با درگاه بعد از پرداخت موفق می‌رود. فروش داشبورد فقط سفارش‌های پرداخت‌شده است |
| امکانات نسخه‌ی اول | علاقه‌مندی‌ها و «موجود شد خبرم کن»، کد تخفیف (و قیمت حراجی)، نظر و امتیاز فقط از خریدار با تأیید ادمین، پیگیری سفارش با پیامک |
| پنل پیامک | ملی‌پیامک با خط خدماتی: فقط پترن تأییدشده، بدون متن آزاد و (تا اینماد ستاره‌دار) بدون لینک. هر جمله‌ی پترن باید فعل داشته باشد. نام کاربری پنل و کلید API به‌جای رمز. متن‌ها: `deploy/sms-patterns.md` |
| مرجوعی و تعویض حضوری (۱۴۰۵/۰۸/۱۲) | در صندوق، با شماره‌ی فاکتور یا موبایل مشتری. کالا با همان مبلغی که مشتری پرداخته (بعد از سهم تخفیف آن فاکتور) پس گرفته می‌شود. تعویض در یک فاکتور: کالای جدید + کالای پس‌گرفته، و تفاوت یا گرفته یا پس داده می‌شود. فروشنده باید در مهلت مرجوعی و طبق «فقط تعویض» باشد؛ مدیر استثنا دارد |
| بستن صندوق (۱۴۰۵/۰۸/۱۲) | نقد مورد انتظار = موجودی اول روز + نقد خالص فروش − هزینه‌های پرداخت‌شده از صندوق. فروشنده می‌شمارد، اختلاف ثبت می‌شود. پولی که در صندوق می‌ماند موجودی اول روز بعد است. بستن دوباره‌ی همان روز جایگزین قبلی می‌شود |
| حسابداری کوچک (۱۴۰۵/۰۸/۱۲) | قیمت خرید روی محصول؛ هنگام هر فروش روی همان قلم ذخیره می‌شود. خرید جنس هزینه نیست. هزینه‌های جاری (اجاره، حقوق، قبوض، تبلیغات …) جدا ثبت می‌شوند. سود ناخالص = فروش خالص − قیمت خرید کالاهای فروخته‌شده؛ سود خالص = سود ناخالص − هزینه‌ها |
| مشتری‌ها (۱۴۰۵/۰۸/۱۲) | هر مشتری با شماره موبایل؛ سفارش‌های سایت و خریدهای حضوری (اگر موبایل در صندوق نوشته شود) یک‌جا. یادداشت خصوصی مدیر برای هر شماره |
| دسترسی کاربران (۱۴۰۵/۰۸/۱۲) | نقش ثابت «فروشنده» جای خودش را به فهرست تیک‌دار دسترسی داد. مدیر کل همه‌چیز را دارد و تنها کسی است که کاربر می‌سازد و دسترسی می‌دهد (تا کسی به خودش دسترسی اضافه نکند). برای هر کاربر دیگر، هر بخش پنل و کارهای ریز داخلش جدا تیک می‌خورد: صندوق (ثبت فروش، تخفیف تا سقف، تخفیف بدون سقف، مرجوعی، استثنا در مرجوعی، دیدن فروش همه، ابطال، بستن امروز، بستن روزهای قبل)، سفارش‌ها، مرجوعی‌ها، انبار، مشتری‌ها، نظرات، محصولات، قیمت خرید (جدا، تا انباردار قیمت خرید را نبیند)، داشبورد، گزارش‌ها، هزینه‌ها و هر بخش تنظیمات. قالب‌های آماده‌ی «فروشنده» و «انباردار» فقط تیک‌ها را پر می‌کنند. هر کار بخش، «دیدن» همان بخش را هم می‌آورد. بخش بدون دسترسی از منو حذف می‌شود و سرور هم ردش می‌کند. فروشنده‌های قبلی همان دسترسی قبلی را گرفتند |
| صفحه‌ی اصلی (۱۴۰۵/۰۸/۱۲) | محصولات اسلایدر چرخان را مدیر انتخاب و مرتب می‌کند (حداکثر ۸)؛ خالی یعنی ویژه‌ها و تازه‌ترین‌ها. بنر تصویری ۴:۳ و نوار متنی بالای سایت، هر کدام با زمان شروع و پایان |
| تم سایت (۱۴۰۵/۰۸/۱۲) | سه رنگ آزاد حذف شد، چون ترکیب‌هایی مثل زمینه‌ی مشکی با رنگ اصلی طلایی پنل را ناخوانا می‌کرد. به‌جایش تم‌های آماده: «روز گرم» و «شب طلایی»، هر کدام با همه‌ی رنگ‌ها دستی تنظیم‌شده. پنل همیشه روشن می‌ماند. تم‌های بیشتر در `globals.css` اضافه می‌شوند |
| بعداً | رهگیری پست و تیپاکس با API خودشان (وقتی API گرفته شد). فید ترب و ایمالز |
| هاست و دامنه | هاست اشتراکی cPanel؛ کد از ریپوی خصوصی گیت‌هاب گرفته می‌شود. بک‌اند روی زیردامنه‌ی api با Setup Python App، سایت روی دامنه‌ی اصلی با Setup Node.js App. راهنما: `deploy/README.md` |
| پوشه‌ی پروژه | `D:\projects-new-erfan\ShivaGallery` (پروژه داخل همین پوشه ساخته می‌شود) |

## مفاهیمی که از ریپوی قبلی نگه می‌داریم

- محصول ← تنوع (رنگ × سایز) با SKU، موجودی و قیمت جدا
- نوع سایزبندی برای هر دسته: حروفی، عددی، فری‌سایز
- دفتر موجودی فقط‌افزودنی (فروش، مرجوعی، اصلاح دستی)
- سفارش با ذخیره‌ی آدرس، قیمت و مشخصات لحظه‌ی خرید و تاریخچه‌ی وضعیت
- سبد مهمان که بعد از ورود با سبد حساب ادغام می‌شود
- دسته‌ها: مانتو، پالتو، شلوار، دامن، بلوز، مجلسی، ست، راحتی، شال و روسری، اکسسوری، کیف و کفش

## نقاط ضعف ریپوی قبلی که باید درست شوند

- تسویه‌حساب ناقص (ارسال، هزینه، پرداخت، صفحه‌ی موفقیت)
- سئوی ضعیف (فقط رندر سمت مرورگر)
- «مقایسه‌ی محصول» بی‌کاربرد برای لباس ← حذف

## سؤال‌های باز

همه‌ی سؤال‌های اولیه جواب گرفتند. سایت مرجع ندارند؛ طراحی با الهام از بهترین فروشگاه‌های مد دنیا پیشنهاد و برای تأیید ارائه می‌شود.
